K8S는 JVM 앱을 어떻게 살리고 죽이는가

Probe부터 OOM Kill까지 — K8S가 JVM 앱을 배포하고, 생사를 판단하고, 트래픽을 제어하고, 종료 시 정리할 시간을 주는 전체 과정을 다룬다.

1. 클러스터 구조

Kubernetes 클러스터는 Control Plane과 Worker Node로 구성된다. Control Plane이 전역적 결정을 내리고, 각 Worker Node의 kubelet이 Pod의 컨테이너를 관리한다.

┌────────────────────────── Kubernetes Cluster ──────────────────────────┐
│                                                                        │
│  ┌─── Control Plane ───┐     ┌──────── Worker Node ────────────────┐  │
│  │                      │     │                                     │  │
│  │  API Server          │     │  kubelet: Pod 관리, Probe 실행      │  │
│  │  Scheduler           │     │  kube-proxy: Service → Pod 라우팅   │  │
│  │  Controller Manager  │     │  Container Runtime: 컨테이너 실행   │  │
│  │  etcd                │     │                                     │  │
│  └──────────────────────┘     │  ┌─Pod─┐  ┌─Pod─┐  ┌─Pod─┐        │  │
│                                │  │ JVM │  │ JVM │  │ JVM │        │  │
│                                │  └─────┘  └─────┘  └─────┘        │  │
└────────────────────────────────────────────────────────────────────────┘

2. Health Check — 세 가지 Probe

JVM 앱은 시작이 느리기 때문에 Probe 설정이 중요하다. 각 Probe가 없으면 어떤 문제가 생기는지 시나리오로 이해하면 역할이 명확해진다.

Probe실패 시 동작핵심 역할외부 의존성?
StartupLiveness/Readiness 비활성화 유지JVM 느린 시작 수용불필요
Liveness컨테이너 재시작좀비 Pod 감지넣지 않는다
ReadinessEndpoint에서 제거일시적 장애 시 트래픽 우회넣는다 (DB, 캐시)

Spring Boot Actuator 연동

# Spring Boot Actuator 연동 예시
startupProbe:
  httpGet:
    path: /actuator/health/liveness
    port: 8080
  initialDelaySeconds: 10
  periodSeconds: 5
  failureThreshold: 36
근거: Kubernetes 공식 문서 — "Startup Probe가 성공할 때까지 Liveness, Readiness Probe는 비활성화된다."
